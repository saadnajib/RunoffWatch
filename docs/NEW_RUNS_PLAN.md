## Why new runs are needed

In all existing runs three things never change: the pesticide (Flufenacet),
the dose (2.4 kg/ha) and the spray date (1 March). A model can only learn from
what varies in its data, so the surrogate cannot say anything about

- spraying on another day of the year,
- another dose,
- another product.

These are exactly the questions asked after the project presentation ("should
I spray today or tomorrow?", "pesticide A or B?"). In the existing data,
"days since spraying" and "day of the year" are also the same thing, so the
surrogate cannot tell the effect of time since spraying from the effect of the
season.

The existing runs also have a numerical problem in the pesticide results
(see [DATA_REPORT.md](DATA_REPORT.md)), which we suspect comes from the Henry
constant 0.03.

## What the experiment contains

Generated by `python -m runoffwatch design` (code: `runoffwatch/design.py`).

**Main group (default 2,000 runs).** Every setting is drawn at random,
independently of the others, so that their effects can be separated:

| Setting | Values |
|---|---|
| Spray date | 26 dates, every 14 days through the year |
| Dose | 600, 1,200 or 2,400 g/ha |
| Half-life in soil (DT50) | 10, 30, 41.68, 90 or 180 days |
| Sorption (Koc) | 30, 100, 377.5, 1,000 or 3,000 |
| Soil and slope | copied from a randomly chosen existing run |
| Weather | one of 40 existing weather files |
| Henry constant | one realistic low value for all runs (default 0.37E-06, the corrected value `rerun` uses; **to be confirmed**) |
| Reference soil moisture | 1 for all runs (the corrected value `rerun` uses; the delivered runs had 100) |

Substances are described by their two key properties (DT50 and Koc), not by
product names. 41.68 days and 377.5 are the values of the existing runs.

**Control group (default 200 runs).** Existing runs repeated exactly as they
were, with only the Henry constant changed. Half of them are runs that broke
numerically, half are runs that did not. If the repeated runs no longer
break, the Henry constant was the cause.

## How to generate the files

```bash
python -m runoffwatch design --n 2000 --controls 200 --name rw_exp1 --out data/design/exp1
```

This writes, into `data/design/exp1/`:

| File or folder | Content |
|---|---|
| `design.csv` | one row per run with all its settings |
| `xrun/` | one run file per run |
| `weather/` | the weather files the runs use |
| `tasks/` | 7z archives of up to 1,000 runs each, in the format the workstation expects |
| `README.txt` | a plain-language description of this particular design |

Nothing is uploaded. Change `--name` for every new submission: the workstation
ignores archives whose name it has seen before.

## Open points to settle with the model owners before submitting

1. **Permission** to submit runs at all.
2. **Spray date.** The model configuration on the workstation has the
   application window written in as a fixed "03-01". The spray date in our run
   files only takes effect if the configuration is changed to read it from the
   run file. Without that change, only the control group is meaningful.
3. **Henry constant.** Which value is right for Flufenacet? Ours is an estimate.
4. **Weather files.** We rebuilt the weather from the PRZM weather files of the
   existing runs. The original Agri4Cast/MARS files would be better: our
   "ET0" column is PRZM's pan evaporation, which may differ by the pan factor
   (0.84), and the workstation may expect files that start in 1975. If the
   originals are available, pass their folder with `--weather-dir`.
5. **Date format.** We write the spray date as month-day (`03-01` = 1 March),
   as in the existing configuration. The crop dates in the same file are
   day-month. Please confirm.
6. **Run time.** About 5 seconds per run means roughly 3 hours for 2,200 runs
   on one core.

## What happens with the results

The result archives have the same format as the existing ones, so the
existing pipeline reads them (`extract`, `inventory`, `qc`, `audit`,
`features`, `train`). Two additions are then needed in the code: dose, DT50
and Koc become model inputs, and "days since spraying" is no longer tied to
the calendar, so the season can come back as a separate input.
